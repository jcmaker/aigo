# AIGO 설계 문서

작성일: 2026-11-05 · 상태: 승인됨

서비스 이름은 AIGO이고, DashPi는 판매하는 블랙박스 상품 이름이다. [사용자]

표기: **[사용자]** 는 사용자가 직접 정한 내용이고, **[Claude 판단]** 은 사용자가 맡겨서 Claude가 정한 내용이다. 표기가 없는 문단은 두 가지를 정리한 설명이다.

## 1. 의도

경기과학기술대학교 캡스톤 프로젝트다. [사용자] 가상의 시나리오로 AIGO 웹 서비스를 만든다. 사람들은 이 사이트에서 블랙박스를 사고, 사고 영상을 올려 AI 분석 레포트를 받는다.

사용자는 두 부류다. [사용자]

- DashPi 블랙박스를 쓰는 사람
- 블랙박스 종류와 상관없이 사고 영상을 분석하고 싶은 사람

두 부류는 서비스 안에서 구분하지 않는다. 같은 화면을 쓰고 같은 레포트를 받는다. [사용자: "그냥 서비스가 잘 동작해야함"]

**성공 기준** [사용자]: 아래 네 가지가 모두 구성되고 실제로 동작한다.

1. 랜딩페이지
2. 상품 1~2개 판매(토스 테스트 결제)
3. 로그인/회원
4. 사고분석(영상 업로드 → 분석 → 평가 → 레포트)

[Claude 판단] 이를 검증하는 시나리오는 다음과 같다. Railway 배포 주소에서 새 계정으로 가입하고, 상품을 테스트 결제해 주문 내역에서 확인하고, 사고 영상을 올려 레포트를 본다. 이 흐름이 처음부터 끝까지 끊기지 않으면 완료다.

## 2. 목표와 비목표

**목표**

- 위 네 기능이 Railway에서 동작한다. [사용자]
- 나중에 모바일 앱을 붙일 수 있도록 API를 제대로 구성한다. 웹은 그 API의 첫 번째 클라이언트일 뿐이다. [사용자]
- 레퍼런스 디자인 수준의 완성도를 갖춘 화면을 만든다. [사용자]

**비목표** [Claude 판단: 지금 만들지 않고, 필요해질 때 추가한다]

- 모바일 앱 자체 (API만 대비)
- 실제 결제, 환불, 배송 처리, 장바구니, 재고 관리
- 관리자 화면 (상품은 시드 데이터로 넣고, 주문은 DB에서 확인)
- 공급자별 개발자 콘솔 설정이 필요한 소셜 로그인 [사용자]. Kakao는 Clerk 공유 자격 증명을 확인하지 못했으므로 뺀다.
- 블랙박스 기기에서 영상을 자동 업로드하는 기능
- 구매자 전용 혜택, 구독, 분석 요금제

**실패로 보는 것** [Claude 판단]

- AI 추정을 법적 판단처럼 보여 주는 것
- 사고가 아닌 영상이나 판단이 어려운 영상에 그럴듯한 레포트를 지어내는 것
- 다른 사용자의 영상이나 레포트가 보이는 것
- 클라이언트가 보낸 금액을 믿고 결제를 승인하는 것
- 측정하지 않은 분석 품질을 좋다고 말하는 것
- 지어낸 후기, 고객 수, 정확도 수치를 랜딩에 넣는 것
- 웹에서만 되고 앱에서는 쓸 수 없는 방식으로 API를 만드는 것

## 3. 구성

```
aigo/
├── apps/api/   FastAPI API와 분석 워커 (같은 코드, 같은 이미지)
├── apps/web/   Next.js 웹
├── apps/app/   모바일 앱 (나중에 추가)
└── docs/
```

| Railway 서비스 | 역할 | 시작 명령 |
|---|---|---|
| web | Next.js | `next start` |
| api | FastAPI, `/api/v1` | `alembic upgrade head` 후 `uvicorn` |
| worker | 분석 작업 처리 | `python -m app.worker` |
| Postgres | 앱 데이터와 작업 대기열 | Railway 관리형 |
| Bucket | 영상 저장 (S3 호환) | Railway 관리형 |

- 스택은 Railway, FastAPI, Next.js다. [사용자]
- [Claude 판단] 나머지는 다음과 같다. Python 3.12, SQLAlchemy 2와 Alembic, Next.js App Router와 TypeScript, Tailwind v4.
- [Claude 판단] 분석은 수십 초에서 수 분 걸리고 메모리를 많이 쓰므로 API 프로세스와 분리한다. 대기열은 Redis 없이 Postgres `FOR UPDATE SKIP LOCKED`로 처리한다. `rizz-shorts`의 워커 구조를 따른다.
- [Claude 판단] api와 worker는 서비스가 다르면 디스크를 공유할 수 없으므로 영상은 Bucket에 둔다. 로컬 개발은 `docker compose`로 Postgres와 S3 호환 저장소를 띄운다.

## 4. API

앱이 웹과 똑같이 쓸 수 있어야 한다는 것이 가장 중요한 제약이다. [사용자]

**규칙** [Claude 판단]

- 경로는 모두 `/api/v1`로 시작한다. FastAPI가 만드는 OpenAPI 문서가 계약이며, 웹의 TypeScript 타입은 여기서 생성한다.
- 오류 응답은 항상 `{"code": "ORDER_AMOUNT_MISMATCH", "message": "사용자에게 보여 줄 한국어 문장"}` 형식이다. 앱은 `code`로 분기한다.
- 목록은 `?limit=&offset=`을 받고 `{"items": [...], "total": n}`을 돌려준다.
- 시간은 UTC ISO 8601, 금액은 원 단위 정수다.

**인증**

Clerk 개발 모드를 쓴다. [사용자] 공급자 콘솔 설정 없이 Clerk 공유 자격 증명으로 켤 수 있는 소셜 로그인과 이메일 로그인을 제공한다.

- [사용자] Clerk 기본 UI는 쓰지 않는다. 로그인, 회원가입, 이메일 코드 확인, 소셜 로그인 버튼, 프로필 화면을 DashPi 디자인 시스템으로 직접 만들고 Clerk 훅과 API로 연결한다.
- [Claude 판단] 웹은 `getToken()`으로 받은 세션 JWT를 `Authorization: Bearer`로 api에 보낸다. 앱도 Clerk 모바일 SDK로 같은 방식을 쓴다.
- [Claude 판단] api는 Clerk 공개키(JWKS)로 JWT를 검증한다. 처음 보는 Clerk 사용자는 `users` 행을 자동으로 만든다.
- [Claude 판단] 쿠키를 쓰지 않으므로 Next.js rewrite가 필요 없다. 웹은 CORS로 api 주소를 직접 호출한다. CORS 허용 출처는 web 주소만 둔다.

**엔드포인트**

| 메서드 | 경로 | 인증 | 설명 |
|---|---|---|---|
| GET | `/me` | 필요 | 내 정보 |
| DELETE | `/me` | 필요 | 탈퇴. 내 영상과 분석, Clerk 사용자를 지운다 |
| GET | `/products` | | 상품 목록 |
| GET | `/products/{slug}` | | 상품 상세 |
| POST | `/orders` | 필요 | 주문 생성. 금액은 서버가 계산한다 |
| POST | `/orders/{id}/confirm` | 필요 | 토스 승인 |
| GET | `/orders` | 필요 | 내 주문 목록 |
| GET | `/orders/{id}` | 필요 | 내 주문 상세 |
| POST | `/analyses` | 필요 | 분석 생성. 분석 ID와 업로드 URL을 돌려준다 |
| POST | `/analyses/{id}/submit` | 필요 | 업로드 완료를 알리고 대기열에 넣는다 |
| GET | `/analyses` | 필요 | 내 분석 목록 |
| GET | `/analyses/{id}` | 필요 | 상태, 레포트, 재생 URL |
| DELETE | `/analyses/{id}` | 필요 | 분석과 영상 삭제 |
| GET | `/health` | | 상태 확인 |

다른 사용자의 주문이나 분석을 요청하면 403이 아니라 404를 돌려준다.

## 5. 사고분석

**참고 범위** [사용자]

`video_ai`와 `accident-counsel`은 참고만 한다. 코드, 화면, 로딩, 레이아웃, 내용을 그대로 옮기지 않는다. `video_ai`는 빠르게 만든 프로토타입이라 입력 품질이 낮으면 결과도 나빠질 위험이 있다. 그래서 파이프라인을 새로 설계하고, 평가 세트로 품질을 측정한 뒤 채택한다.

**분석 원칙** [Claude 판단]

1. **입력을 먼저 고친다.** 고정 프레임률 mp4로 정규화하고, 해상도와 프레임 품질을 확인한다.
2. **충돌 순간을 먼저 찾는다.** 전체를 균등하게 몇 장 뽑으면 짧은 접촉 순간을 놓친다. 넓게 훑고 후보 구간만 촘촘히 본다.
3. **관찰과 판단을 나눈다.** 모델은 먼저 영상에서 보이는 사실만 시각과 함께 적고, 그 사실로만 판단한다.
4. **숫자는 코드가 계산한다.** 모델은 기준 표에서 도표와 수정요소를 고르기만 한다. 과실 범위는 코드가 낸다.
5. **모르면 모른다고 한다.** 근거가 없는 항목은 `unknown`으로 두고, 맞는 도표가 없으면 과실비율을 내지 않는다.
6. **모든 주장에 근거 시각을 붙인다.** 시각이 없거나 영상 범위를 벗어난 주장은 코드가 버린다.
7. **신뢰도를 모델에게 묻지 않는다.** 충돌 시점 확보 여부, 근거 수, `unknown` 수로 코드가 `높음`, `보통`, `낮음`을 낸다.
8. **측정 없이 바꾸지 않는다.** 프롬프트, 모델, 샘플링을 바꾸면 평가 세트를 다시 돌린다.

**흐름** [Claude 판단]

1. 클라이언트가 파일 이름, 크기, 동의 값(`consent=true`)을 담아 `POST /analyses`를 호출한다. api가 형식과 크기, 하루 제한을 확인하고 15분짜리 서명 업로드 URL을 돌려준다.
2. 클라이언트가 Bucket에 직접 올린 뒤 `POST /analyses/{id}/submit`을 호출한다. 분석 행이 `queued`가 된다. Clerk 토큰은 약 1분이면 만료되므로, 큰 파일을 api로 받으면 업로드 중에 인증이 끊길 수 있어 이 방식을 쓴다.
3. worker가 작업을 가져가서 단계마다 `stage`를 갱신한다.
   - `normalize`: `ffprobe`로 실제 영상인지와 길이를 확인하고, 30fps 고정 H.264 mp4로 변환한다. 원본 해상도는 분석용으로 유지하고 재생용은 720p로 만든다.
   - `scan`: 초당 5장으로 전체를 훑으며 YOLO와 ByteTrack으로 객체를 추적한다.
   - `locate`: 충돌 후보 시각을 최대 3개 고른다. 후보 신호는 객체 박스 급팽창과 최근접, 화면 전체가 흔들리는 순간, 소리의 급격한 상승이다. 소리가 없거나 음악이 섞이면 소리 신호는 뺀다.
   - `focus`: 후보 앞 3초에서 뒤 2초를 초당 15장으로 다시 뽑고, 그중 신호등, 차선, 상대 차가 잘 보이는 대표 프레임을 원본 해상도로 고른다. 번호가 붙은 박스를 그린 프레임과 좌표 글을 함께 준비한다.
   - `observe`: 비전 모델이 대표 프레임을 보고 사실만 적는다. 당사자 여부, 도로 형태, 진행 방향, 신호, 차선, 상대 움직임, 충돌 시각, 안 보이는 항목이 대상이다.
   - `assess`: 관찰 결과로 후보 도표를 좁히고, 모델이 도표와 수정요소를 고른다. 코드가 도표와 수정요소, 시각을 검증하고 과실 범위와 신뢰도를 계산한다.
4. 클라이언트는 `GET /analyses/{id}`를 3초마다 호출해 단계, 중간 결과, 최종 레포트를 받는다. 화면을 닫아도 분석은 계속되고 내 분석 목록에서 다시 볼 수 있다.

SSE는 쓰지 않는다. 폴링이 웹과 앱에서 똑같이 동작하고 더 단순하다.

**과실 기준 데이터** [Claude 판단]

손해보험협회 과실비율정보포털의 도표를 원천으로 쓴다. `accident-counsel`의 기준 표는 8개뿐이므로, 평가 세트와 샘플 영상에 나오는 사고 유형을 기준으로 늘린다. 도표마다 출처 URL을 저장해 레포트에 링크한다. 맞는 도표가 없으면 사고 분석은 보여 주고 과실비율은 "기준 도표를 찾지 못했습니다"로 표시한다.

**제한** [Claude 판단, 모두 환경변수로 조정]

- 형식: mp4, mov, webm, avi
- 크기: 200MB
- 길이: 2분
- 사용자당 하루 5건, 서비스 전체 하루 100건. 계정을 새로 만들어도 OpenAI 비용이 일정 수준을 넘지 않게 한다. 사용자 한도는 실패한 분석을 세지 않고, 서비스 전체 한도는 실패도 비용이 들므로 함께 센다.

**실패 처리** [Claude 판단]

- 단계 하나가 실패하면 `failed`로 두고 사용자에게 보여 줄 이유를 남긴다. 사용자는 영상을 다시 올린다.
- 충돌 후보가 없으면 균등 샘플로 `observe`를 진행하고 신뢰도를 `낮음`으로 둔다. 객체 추적이 실패해도 후보가 있으면 후보 프레임을 쓴다.
- 모델 응답이 스키마나 코드 검증을 통과하지 못하면 오류를 알려 주고 한 번만 다시 요청한다. 또 실패하면 `failed`로 둔다.
- worker가 죽어 10분 넘게 `processing`에 머문 작업은 한 번 다시 대기열에 넣고, 두 번째에는 `failed`로 둔다.

**레포트 내용** [사용자: 분석, 평가, 레포트]

레포트 스키마와 문구는 새로 정한다. [Claude 판단] 다음 내용을 담는다.

- 결론: 사고 유형, 예상 과실 범위, 신뢰도
- 분석: 요약, 근거 시각이 붙은 타임라인, 충돌 시각, 확인된 사실, 확인할 수 없는 사실
- 평가: 기준 도표, 기본과실, 수정요소별 증감과 근거 시각, 12대 중과실 가능성(`high`, `medium`, `low`, `unknown`), 심각도
- 내게 유리한 점과 불리한 점
- 안내: 지금 해야 할 행동, 이후 대응 방법
- `involvement`: `party`(촬영 차가 당사자), `witness`(제3자 사고), `none`(사고 없음 또는 판단 불가) 중 하나다. `witness`는 분석만 보여 주고 과실비율을 비운다. `none`은 `reason`만 보여 준다.

음주, 무면허처럼 영상으로 확인할 수 없는 항목은 `unknown`으로 둔다. 모든 레포트에 "영상 기반 AI 추정이며 법적 판단이 아닙니다" 안내를 고정으로 표시한다. 이 문구는 모델 출력이 아니라 화면 코드에 둔다.

**분석 진행과 레포트 화면** [Claude 판단]

- 진행 화면은 단계와 실제 중간 결과(후보 시각, 대표 프레임 등)를 새로 설계해 보여 준다. 기존 프로젝트의 로딩 화면을 따르지 않는다.
- 레포트에서 영상 위에 객체 박스를 겹쳐 재생하고, 근거 시각을 누르면 그 장면으로 이동한다.
- PDF 저장은 인쇄 전용 CSS와 `window.print()`로 처리한다.

**모델** [Claude 판단]

OpenAI를 쓰고 모델은 `OPENAI_MODEL` 환경변수로 둔다. 기본 후보는 `accident-counsel`이 영상 3개로 비교해 채택한 `gpt-5.5` + `reasoning_effort=low`다. 표본이 작으므로 평가 세트로 다시 고른다. `gpt-5.4-mini`는 같은 비교에서 도표를 잘못 골랐다.

**개인정보** [Claude 판단]

영상에는 번호판과 얼굴이 담기고 프레임이 OpenAI로 전송된다. 업로드 화면에서 이 사실을 알리고 동의를 받는다. Bucket은 비공개로 두고 재생은 1시간짜리 서명 URL로만 한다. 삭제나 탈퇴를 하면 파일까지 지운다.

## 6. 커머스

**상품**

상품은 1~2개다. [사용자] [Claude 판단] 표준형과 상위형 2종을 시드 데이터로 넣는다. 이름, 가격, 사양은 구현 시점의 임시값이며 시드 파일만 고치면 바뀐다.

**구매 흐름** [Claude 판단]

장바구니 없이 상품 상세에서 바로 산다. 로그인이 필요하다.

1. 상품 상세에서 수량을 고르고 구매를 누른다.
2. 체크아웃에서 받는 사람, 연락처, 주소를 입력한다. 주소는 일반 입력 칸으로 받는다.
3. `POST /orders`가 DB 가격으로 금액을 계산해 `pending` 주문을 만든다. 주문 ID는 토스 규칙에 맞게 만든다.
4. 토스 결제위젯 v2로 결제한다. `successUrl`로 돌아오면 `POST /orders/{id}/confirm`을 호출한다.
5. 서버가 주문 금액과 `amount`를 비교해 다르면 거절한다. 같으면 토스 `/v1/payments/confirm`을 호출해 `paid`로 바꾼다. `Idempotency-Key`를 쓰고, 이미 `paid`인 주문은 그대로 성공을 돌려준다.
6. 완료 화면을 보여 주고 주문은 내 주문에서 볼 수 있다.

**토스 키**

토스는 테스트 기능만 쓴다. [사용자] 공개키만으로는 결제를 끝낼 수 없다. 토스 문서상 승인 API에 시크릿 키가 필요하고, 클라이언트 키와 시크릿 키가 한 세트여야 한다. [Claude 판단] 토스 공식 연동 가이드의 문서용 테스트 키 세트(`test_gck_...`, `test_gsk_...`)를 쓴다. 클라이언트 키는 `NEXT_PUBLIC_TOSS_CLIENT_KEY`, 시크릿 키는 api 서비스의 `TOSS_SECRET_KEY`에만 둔다. 서버는 `test_`로 시작하지 않는 키를 받으면 시작하지 않는다.

체크아웃과 주문 화면에 "테스트 결제입니다. 실제로 청구되지 않습니다"를 표시한다.

## 8. 디자인

[사용자] 레퍼런스는 `rizz-shorts`와 getartcraft.com/apps(디자인 시스템, 레이아웃, 애니메이션, 효과)다. 두 곳은 따뜻한 종이색 바탕(`#f2f1ee`)과 Geist Mono를 공유해서 잘 어울린다.

[Claude 판단] 두 레퍼런스에서 가져오는 것은 다음과 같다. ArtCraft의 로고, 이미지, 문구는 쓰지 않는다.

- **`rizz-shorts`에서**: `tokens.css`의 토큰 체계(바탕, 글자, 선, 글자 단계, 간격, 폭, 움직임), 1280 틀과 1px 선 격자, 랜딩의 각진 모서리와 그림자 없는 면, 48px 위 막대, Pretendard와 Geist Mono, 기본 OS 설정을 따르는 밝은/어두운 테마
- **ArtCraft에서**: `01/` 번호 섹션 라벨, 번호와 상태 배지가 붙은 카드 나열, 번호 붙은 원칙 목록, 마지막 CTA 띠, 4열 푸터, 흐르는 띠(36초 등속), 스크롤에 맞춘 절제된 등장 효과
- **강조색**: ArtCraft 계열 파랑(`#2d81ff`, 글자용 `#1659c4`). 빨강은 심각도와 오류 전용으로 남겨 사고 화면에서 의미가 흐려지지 않게 한다.

`prefers-reduced-motion`을 존중하고, 키보드 포커스를 표시하고, 360px 폭에서도 가로 스크롤이 생기지 않아야 한다.

## 10. 검증

[Claude 판단] 외부 서비스는 테스트에서 가짜로 바꾼다.

- API 테스트: Clerk JWT 검증(가짜 키 쌍 사용), 금액 위조 거절, 중복 승인, 다른 사용자 접근 404, 업로드 검증, 하루 제한, 작업 가져가기와 재시도
- 분석 테스트: 짧은 샘플 영상으로 worker 전체를 돌리고 OpenAI 응답만 고정값으로 바꾼다
- 품질 평가: `사고영상/`에서 고른 15개 이상과 사고가 없는 영상 3개로 평가 세트를 만든다. Claude가 초안을 만들고 팀이 정답을 확인한다. `python -m app.evaluate`가 결과표를 만든다.

| 지표 | 합격선 |
|---|---|
| 충돌 시각 오차 1초 이내 | 80% 이상 |
| 정답 도표 선택 | 70% 이상 |
| 정답 과실이 범위 안에 포함 | 70% 이상 |
| 사고 없는 영상에 과실비율을 낸 경우 | 0건 |
| 근거 시각이 실제 장면과 맞음 | 표본 검사 90% 이상 |
| 2분 이하 영상 처리 시간 | Railway에서 90초 이내 |

합격선은 Claude가 정한 초기값이다. 측정 결과를 본 뒤 조정할 수 있다.
- Playwright: 가입 → 테스트 결제 → 업로드 → 레포트
- 배포 후: 1장의 시나리오를 Railway 주소에서 직접 실행하고, 실제 OpenAI 호출과 토스 테스트 결제까지 확인한다
