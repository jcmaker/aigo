# 분석 진행 화면: 살아 있는 체크리스트 (앱)

## 왜

분석 중 화면은 단계가 바뀔 때만 달라진다. "장면 관찰"·"기준과 대조"처럼 AI를 부르는 단계는 수십 초 걸리는데, 그동안 화면이 그대로라 사용자는 멈췄는지 진행 중인지 알 수 없다. [사용자]

## 목표 / 비목표

- 목표: 단계가 바뀌지 않아도 화면이 계속 살아 있게 해, "진행 중"임을 한눈에 알게 한다.
- 비목표: 서버(apps/api) 변경, AI 생각 과정 스트리밍, 남은 시간 예측, 웹 화면(같은 방식으로 따로 PR).
- 반목표: 실제로 측정하지 않은 숫자를 진행 중 문구에 넣는 것(예: "차량 5대를 찾았어요"). 지어낸 진행률을 정확한 것처럼 보이게 하는 것.

## 고른 방식

시안 캔버스(https://claude.ai/artifact/BCC9RkcmLpTRDjEvwXtcR9)에서 세 가지를 비교했다.

- **A. 살아 있는 체크리스트 (선택)** [사용자]: 지금 단계 목록을 유지하고 진행 중 단계에 회전 링, 경과 초, 바뀌는 안내 문구를 더한다. 앱만 고치면 된다.
- B. 레포트 스켈레톤: 레포트 모양 빈칸이 단계마다 채워진다. 단계 안에서는 여전히 정지하고, 한 줄씩 채우려면 서버 변경이 필요하다.
- C. AI 작업 기록: AI 문장이 한 줄씩 타이핑된다. 서버 스트리밍이 필요하고, 다듬지 않은 문장이 노출될 위험이 있다.

## 설계

`apps/app/src/components/analysis.tsx`의 `ProgressView`와 `ui/StepList`를 바꾼다. 데이터는 지금 API 그대로 쓴다(`progress[]`의 `status`, `at`).

1. **위 카드**: 반원 게이지 대신 시안 A의 카드. `n/6 단계` · `경과 m:ss` 한 줄, 큰 제목(`doing`), 2.6초마다 바뀌는 단계별 안내 문구(페이드), 진행 막대.
   - 경과 시간: 첫 단계 기록의 시각부터 지금까지 1초마다 센다. 대기열(단계 기록 없음)에서는 "곧 분석을 시작해요"만 보이고 시간은 세지 않는다. [Claude 판단: 업로드 대기 시간을 분석 시간에 섞지 않으려고]
   - 진행 막대: 끝난 단계 수 + 진행 중 단계의 경과 비율(단계별 보통 소요 시간으로 나눠 최대 90%까지)로 채우고, 위로 빛이 지나가는 효과를 준다. 100%는 완료 때만. [Claude 판단]
2. **단계 목록**: 끝난 단계는 체크가 튀어나오듯 나타나고(scale) 결과 문구를 보인다(지금과 같은 `stageResult`). 진행 중 단계는 회전 링 + 은은한 숨쉬기 그림자, 오른쪽에 `n초`(그 단계 `at`부터), 아래에 안내 문구. 대기 단계는 회색.
   - 끝난 단계의 소요 초는 표시하지 않는다. 서버가 완료 시각으로 `at`을 덮어써 첫 단계 시작을 알 수 없기 때문이다. [Claude 판단]
3. **안내 문구**: 단계마다 2~4개, 숫자 없이 어느 영상에도 맞는 문장. 예: 장면 관찰 → "신호등과 차선을 확인하고 있어요", "충돌 직전 장면을 다시 보고 있어요". 실패·중단 화면, 연결 불안정 문구, "화면을 닫아도 분석은 계속돼요" 안내는 지금 그대로.
4. **시계**: 서버 시각과 폰 시각 차이로 음수가 나오면 0으로 둔다. 1초 타이머는 화면이 보일 때만 돈다.
5. **모션**: React Native `Animated`(네이티브 드라이버)로 회전·페이드·튀어나옴. 새 라이브러리는 넣지 않는다. 시스템 "동작 줄이기"가 켜져 있으면 회전·빛 효과를 끈다.
6. **접근성**: 진행 중 단계의 읽기 문구에 경과 초를 넣지 않는다(1초마다 다시 읽히지 않게). 단계가 바뀔 때만 알린다.

## 기록

화면 결정은 ADR로 남긴다(docs/adr/0033).

## 빌더에게 남긴 것

- 안내 문구의 정확한 표현과 막대 비율 상수.
- `StepList`를 다른 화면이 쓰면 기존 모양을 유지하는 방식(새 prop 또는 별도 컴포넌트).
