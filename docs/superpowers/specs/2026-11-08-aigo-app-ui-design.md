# AIGO 앱 UI 디자인

2026-11-08. 앱 1차 기능 구현(`2026-11-06-aigo-app-design.md`) 위에 화면 디자인을 입힌다.

## 목적

지금 앱은 기능 확인용 최소 스타일이다(`apps/app/src/components/ui.tsx`). 이 작업은 같은 기능과 흐름에 실제 서비스 수준의 디자인을 입힌다.

사용자는 사고 직후 긴장한 상태로 앱을 연다. 그래서 다음 두 가지를 원칙으로 한다.

- 한 화면에 핵심 하나만 크게 보여 준다.
- 긴급 기능은 어디서든 한 번에 열린다.

## 목표

- 디자인 시스템(토큰과 컴포넌트)을 만들고 모든 화면에 적용한다.
- 앱을 열 때 로고 모션을 보여 준다.
- 하단 메뉴를 5개로 늘린다.

## 하지 않는 것

- 새 기능을 만들지 않는다. 지금 있는 기능과 API 응답만 화면에 배치한다. 참고 시안의 기기 연결, 프로필 수정, 앱 설정, 도움말 화면은 만들지 않는다.
- 다크 모드는 만들지 않는다(밝은 화면 하나).
- 별도 글꼴을 넣지 않는다(폰 기본 글꼴).
- 스토어 출시용 스크린샷과 소개 문구는 만들지 않는다.

## 실패로 보는 것

- 흔한 AI 생성 화면처럼 보이는 것. 의미 없는 그라데이션, 장식용 아이콘 남발, 모든 카드에 같은 무게를 주는 배치가 여기에 해당한다.
- 사고 현장 모드가 모션이나 로그인 때문에 늦게 열리는 것.
- 기존 동작(업로드, 구간, 공유, 오프라인 현장 모드, 공유받기)이 깨지는 것.

## 브랜드

- **로고:** 원본 로고(로열 블루 + 청록)를 Supabase 색으로 바꾼 A안을 쓴다. 바탕은 `#1C1C1C`, A는 흰색, 길과 화살표, 별은 `#3FCF8E`다.
- **로고 원본 위치:** 사용자의 `~/Downloads`에 있는 PNG 3개(앱 아이콘, 심볼, 가로 로고)다. 색을 바꾼 결과와 모션용 레이어(A, 길과 화살표, 별)는 스크립트로 만들었다. 앱에 넣을 때는 `apps/app/assets/brand/`에 PNG로 둔다.
- **앱 아이콘과 Android 적응형 아이콘:** A안 아이콘에서 만든다.
- **진입 모션 "길 그리기" (약 1.4초):**
  1. 0~0.45초에 A가 아래에서 떠오른다.
  2. 0.3~1.0초에 길과 화살표가 왼쪽에서 오른쪽으로 드러난다.
  3. 1.0~1.4초에 별이 회전하며 커진다.
  4. 1.05초부터 "AIGO" 글자가 떠오른다.

## 글자, 간격, 모서리

- **글자:** 폰 기본 글꼴을 쓰고, 숫자는 고정폭(`fontVariant: ['tabular-nums']`)으로 쓴다.

  | 단계 | 크기 / 굵기 | 용도 |
  |---|---|---|
  | Display | 34 / 800, 자간 -1 | 핵심 숫자 |
  | Title | 24 / 800, 자간 -0.5 | 화면 제목 |
  | Headline | 17 / 700 | 카드 제목 |
  | Body | 15 / 400 | 본문 |
  | Label | 13 / 600 | 탭, 칩, 행 제목 |
  | Caption | 13 / 400 | 보조 설명 |
  | Micro | 11.5 / 500 | 타일 라벨 |

- **간격:** 4 단위(4, 8, 12, 16, 20, 24, 32)다. 화면 좌우 여백 16, 카드 안 여백 16, 카드 사이 12를 쓴다. 하단 메뉴가 떠 있으므로 탭 화면의 스크롤 끝에 메뉴 높이와 안전 영역만큼 여백을 둔다.
- **모서리:** 카드 24, 영상 20, 행과 타일 16, 입력칸 14, 아이콘 상자 12다. 버튼, 칩, 하단 메뉴는 완전한 둥근 모양이다.
- **그림자:** 하단 메뉴에만 쓴다. 카드는 그림자 없이 바탕색 차이로 구분한다(토스 방식).

| `Icon` | 이름 하나로 SVG 아이콘 | 전체 |

- **하단 메뉴 (TennisIQ 방식):**
  - 모양: 짙은 반투명 알약(`ink`, 불투명도 0.92)을 화면 아래에 띄운다. 아이콘 칸은 46, 안쪽 여백은 7이다.
  - 아이콘: 글자 없이 아이콘만 둔다. 선택한 탭은 `brand` 원에 `ink` 아이콘이고, 선택 원은 탭 사이를 미끄러지듯 움직인다.
  - 접근성: 각 버튼에 화면 읽기용 이름(홈, 내 분석, 분석하기, 현장 모드, 계정)을 붙인다.
  - 순서와 현장 모드: 순서는 홈, 내 분석, 분석하기, 현장 모드, 계정이다. 현장 모드 아이콘만 선택되지 않았을 때도 `sceneIcon` 색이다.
- **반원 게이지:** 둥근 칸을 반원에 배치한다. 반원을 N칸으로 나누고 칸 사이를 띄운다.
  - 진행 화면: 6칸 중 끝난 단계는 `brand`, 진행 중인 단계는 `brand400`, 남은 단계는 `gray4`다. 가운데에 "단계 4/6"과 지금 하는 일을 쓴다.
  - 레포트: 10칸(10%씩) 중 `my_min`~`my_max` 범위만 `brand`다. 가운데에 "예상 범위"와 `20~40%`를 쓴다. 과실이 없으면 게이지 대신 사유 문장을 보여 준다.

## 화면

참고 HTML의 흐름을 따르되, 화면 수와 내용은 지금 기능 그대로다.

| 화면 | 구성 |
|---|---|
| 진입 | `ink` 바탕에 로고 모션이 나온다. 자세한 동작은 아래 "진입 모션 동작"을 따른다. |
| 로그인 | 가로 로고, 제목, `TextField` 2개, 주 버튼, 회원가입 링크, 소셜 버튼 3개(`secondary`), 맨 아래 현장 모드(`danger`) |
| 회원가입·인증 | 같은 구성이다. 인증 단계는 `CodeInput`, 확인 버튼, 코드 다시 받기와 이메일 다시 입력 링크다. |
| 홈 | 로고와 계정 원형 버튼, `HeroCard`("내 분석", 전체·완료·분석 중 `StatTile` 3개), 버튼 2개(영상 분석하기, 사고 현장 모드), 최근 분석 카드(앞쪽 3개 `ListRow`, 전체 보기) |
| 내 분석 | 제목, 카드 안 `ListRow` 목록(썸네일 칸, 제목, 번호·날짜·내 과실, 상태 칩), 빈 상태 |
| 분석하기 | `VideoFrame`, `TrimBar`, 구간 버튼 3개(`md secondary`), 다른 영상 고르기, 형식 안내, 동의 `Notice`와 `ConsentSwitch`, 맨 아래 주 버튼. 영상을 고르기 전에는 "어떤 영상을 분석할까요?" 빈 상태와 갤러리 버튼 |
| 분석 진행 | `TopBar`(분석 번호, 날짜), `SegmentGauge` 6칸, `StepList`, 안내 `Notice` |
| 레포트 | `TopBar`(사고 유형, 내 차 사고 또는 제3자 사고와 날짜, 오른쪽 PDF 공유 버튼), `SegmentedControl` |
| 레포트 · 요약 | 내 과실 `SegmentGauge`, `StatTile` 3개(신뢰도, 기준 도표, 기본과실), AI 주의 `Notice`, 신뢰도 설명 |
| 레포트 · 근거 | `VideoFrame`, 확인한 장면 `ListRow`(`TimeChip` → 영상 이동), 그 밖에 확인된 사실 |
| 레포트 · 기준 | 기준 도표, 기본과실, 수정요소, 영상으로 판단하지 못한 요소. 맨 아래에 분석 삭제(`danger`) |
| 계정 | 이메일 카드, 상품 보기 `ListRow`, 로그아웃과 탈퇴(`danger600` 글씨) `ListRow` |
| 사고 현장 모드 | 112, 119 `emergency` 버튼을 가장 위에 둔다. 체크리스트 카드, 현장 사진 촬영(`dark`), 보험사 번호 `TextField`와 저장, 전화 버튼. 로그인 후에는 `emergency` 탭으로 열려 하단 메뉴가 보이고, 로그인 전에는 메뉴 없는 `/scene` 화면으로 열린다. |
| 현장 사진 | 사진 3열 그리드, 선택한 사진의 시각과 위치(없으면 "위치 정보 없음"), 공유와 삭제 |
| 공유받은 영상(로그인 전) | `EmptyState`(자물쇠 아이콘, "로그인이 필요합니다"), 로그인하러 가기, 사고 현장 모드 |

- **실패, 대기, 업로드 미완료:** 레포트 대신 기존 문구와 "영상 다시 올리기" 버튼을 카드로 보여 준다.
- **문구:** 기존 문구를 유지한다. 새로 생기는 빈 상태와 안내만 토스처럼 질문형이나 "~해요"체로 쓴다.

## 탭 구조 변경

- `(tabs)`를 `home`, `analyses`, `upload`, `emergency`, `account` 5개로 바꾼다.
- **현장 모드 경로:** 루트 `scene/` 스택(`/scene`, `/scene/photos`)은 지금 그대로 둔다. 로그인 검사 밖에 있으므로 로그아웃 상태와 오프라인에서도 열린다.
  - 탭은 `(tabs)/emergency.tsx`(`/emergency`)다. `scene/index.tsx`의 화면 본문을 컴포넌트로 빼서 두 곳이 같이 쓴다.
  - 현장 사진은 두 곳 모두 `/scene/photos`로 push한다(하단 메뉴 없음).
  - 로그인 화면, 공유 안내, 진입 화면의 현장 모드 버튼은 계속 `/scene`으로 간다.
- **분석하기 탭(`upload`):** 지금 `upload.tsx`를 탭으로 옮긴다.
  - 탭을 오가도 고른 영상, 구간, 동의, 진행 상태를 유지한다. 업로드 중에 다른 탭으로 가도 업로드는 계속된다.
  - 업로드가 끝나 `/analyses/[id]`로 이동할 때 상태를 모두 초기화한다. 고른 영상, 구간, 동의, `attempt`가 대상이다.
  - 공유받기는 지금처럼 `params`(uri, name, size)로 들어온다. 새 `params`가 오면 이전 상태를 버리고 새 영상으로 시작한다. 이미 만든 분석(`attempt`)이 있고 업로드가 끝나지 않았다면, 기존 구간 잠금 규칙대로 "다른 영상 고르기"와 같은 처리를 한다.
- **하단 메뉴 없는 화면:** 레포트(`/analyses/[id]`), 현장 사진, 공유 안내는 탭 밖 스택이다.
- **이동 경로:** 공유받기와 알림 이동은 지금처럼 `/upload`와 `/analyses/[id]`로 간다. `/upload`는 탭 경로가 된다.

## 진입 모션 동작

- **위치:** `Splash`는 루트 `index.tsx` 안에 둔다. 공유나 알림으로 시작하면 `+native-intent`가 다른 경로로 보내므로 모션을 건너뛴다.
- **재생:** 앱을 새로 시작할 때 한 번만 1.4초를 다 보여 준다. 모션이 끝나고 Clerk 로딩도 끝나면 로그인 또는 홈으로 `replace`한다.
- **로딩이 끝나지 않을 때:** 모션이 끝나도 Clerk가 로드되지 않으면(오프라인 등) 로고를 멈춘 채 지금처럼 "불러오는 중"과 사고 현장 모드 버튼을 보여 준다.
- **현장 모드 버튼:** 모션 중에도 화면 아래에 보이고 누를 수 있다.

## 데이터 매핑

- **홈 숫자:** 기존 목록 API(`limit=100`)로 센다. 100건을 넘으면 "100+"로 표시한다.
  - 전체: 목록 수
  - 완료: `done`
  - 분석 중: `queued` + `processing`
  - 실패와 업로드 미완료는 전체에만 들어간다.
- **썸네일 칸:** 서버에 썸네일이 없으므로 회색 상자에 영상 아이콘을 넣는다. 새 의존성은 쓰지 않는다.
- **레포트 탭 배분:** 지금 `components/analysis.tsx`가 그리는 항목을 그대로 나눈다. 필드 이름은 코드를 따른다.

  | 탭 | 항목 |
  |---|---|
  | 요약 | 사고 유형, 관여, 신뢰도와 설명, 내 과실, 미확인일 때의 안내 문구 |
  | 근거 | 영상, 시각이 있는 근거(지금 `onSeek` 버튼이 붙는 항목), 그 밖에 확인된 사실 |
  | 기준 | 기준 도표, 기본과실, 수정요소, 영상으로 판단하지 못한 요소, 분석 삭제 |

  시각이 있는 항목만 `TimeChip`을 쓰고, 시각이 없는 항목은 칩 없이 행만 보여 준다.
- **소셜 로그인 버튼:** 지금처럼 글자만 쓴다("Google로 계속하기" 등). 제공자 로고는 넣지 않는다.

## 브랜드 파일

- **변형:** 최종은 다크(A안)다. 구현 때 다음 파일을 `apps/app/assets/brand/`에 넣고 커밋한다.
  - `icon-dark.png`: 앱 아이콘
  - `layer-a.png`, `layer-road.png`, `layer-star.png`: 모션
  - `wordtext-light.png`: 진입 화면의 흰 "AIGO" 글자
  - `wordmark-dark.png`: 밝은 화면의 가로 로고
- **만드는 방법:** 원본 PNG에서 색을 바꾸는 스크립트를 `apps/app/scripts/brand.py`로 저장소에 둔다. 다른 환경에서도 다시 만들 수 있게 하기 위해서다. 원본 PNG 3개도 `apps/app/assets/brand/source/`에 넣는다.
- **`app.json`:**
  - 아이콘: `icon-dark.png`(1024)
  - Android 적응형 아이콘: 바탕은 `#1C1C1C` 단색이다. foreground는 바탕 없는 로고를 안전 영역(가운데 66%)에 맞춰 줄인 PNG이고, monochrome은 같은 모양의 흰색이다.
  - 스플래시: `#1C1C1C` 바탕에 모션 첫 장면과 같은 A만 둔다. 네이티브 스플래시에서 JS 모션으로 이어질 때 끊겨 보이지 않게 하기 위해서다.

## 의존성

- **추가:** `react-native-svg` 하나만 `npx expo install`로 넣는다. 아이콘과 게이지에 쓴다. 네이티브 모듈이므로 `rm -rf android` 뒤 다시 빌드해야 한다.
- **아이콘:** 쓰는 아이콘이 15개 안팎이라 라이브러리 대신 SVG 경로로 직접 둔다.
- **모션:** 진입 모션, 하단 메뉴의 선택 원, 버튼 눌림은 React Native `Animated`로 만든다. `react-native-reanimated`는 이미 설치돼 있지만 직접 쓰지 않는다.
