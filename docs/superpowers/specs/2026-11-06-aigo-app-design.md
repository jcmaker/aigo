# AIGO 모바일 앱 설계

표시: [사용자]는 사용자가 정한 것, [Claude 판단]은 사용자가 뒤집을 수 있는 내 판단이다.

## 목적

웹이 나중에 책상에서 보는 도구라면, 앱은 사고 직후 현장에서 쓰는 도구다. [사용자 승인]
iOS와 Android를 구분하지 않고 한 코드로 만든다. [사용자] UI는 나중에 정하고 지금은 기능이 동작하는 기본 화면만 만든다. [사용자]

## 범위

기본 기능 [사용자 승인]
- 로그인, 회원가입, 소셜 로그인. Clerk 기본 UI는 쓰지 않는다.
- 영상 선택, 업로드, 분석 진행 상태, 레포트, 분석 내역과 삭제, 회원 탈퇴

앱 전용 기능 [사용자 승인]
- 분석 완료 푸시
- 사고 현장 모드
- 영상 구간 자르기, 다른 앱의 공유 메뉴에서 영상 받기
- 레포트 공유

상품 구매는 앱에 새로 만들지 않고 기존 웹 페이지를 연다. [사용자 승인]

하지 않는 것
- UI 디자인과 애니메이션
- 앱을 닫아도 계속되는 백그라운드 업로드. 업로드 중에는 화면을 켜 둔다. [Claude 판단]
- DashPi 기기 연결과 라즈베리파이 작업 [사용자]
- 스토어 배포와 Apple Developer 가입. 필요할 때 따로 한다. [사용자]

## 구조

`apps/app`(Expo)은 웹과 같은 `/api/v1`을 쓴다. 분석 파이프라인의 판단 로직은 바꾸지 않는다.
타입은 `apps/web/openapi.json`에서 생성해 웹과 같은 계약을 쓴다. [Claude 판단]

주요 라이브러리 [Claude 판단]: Expo Router, `@clerk/expo`, `expo-secure-store`, `expo-auth-session`, `expo-web-browser`, `expo-image-picker`, `expo-video`, `expo-file-system`, `expo-sharing`, `expo-print`, `expo-notifications`, `expo-location`, `expo-keep-awake`

## API 변경

### 로그인 토큰

현재 서버는 `azp`가 없는 토큰을 거부한다. Clerk 문서는 `azp`가 없으면 검사를 건너뛰어도 된다고 한다.
실제 앱 토큰을 먼저 확인한다. 없으면 `azp`가 있을 때만 허용 목록과 비교하도록 `auth.py`를 고친다. 있으면 허용 목록만 맞춘다.

### 기기 등록

`push_devices` 표: `token`(기본키), `user_id`(users 삭제 시 함께 삭제), `platform`, `updated_at`

- `POST /api/v1/devices` `{token, platform}`: 등록한다. 같은 토큰이 있으면 현재 사용자로 옮긴다. Expo 토큰 형식만 받는다.
- `DELETE /api/v1/devices?token=...`: 내 토큰만 지운다. 로그아웃할 때 부른다.

### 분석 완료 푸시

worker가 최종 `done`이나 최종 `failed`를 DB에 저장한 뒤 Expo Push로 보낸다.
- 재시도로 넘어가는 실패에는 보내지 않는다.
- 발송 실패는 로그만 남긴다. 분석 결과에 영향을 주면 안 된다. 타임아웃은 5초다.
- `DeviceNotRegistered` 응답을 받은 토큰은 지운다.
- 잠금 화면에 보이므로 문구에 사고 내용을 넣지 않는다. 제목 "AIGO", 본문 "분석이 끝났습니다." 또는 "분석에 실패했습니다."
- `data.analysis_id`로 알림을 누르면 해당 레포트를 연다.

### 구간 자르기

폰에서 영상을 자르면 네이티브 라이브러리가 늘어난다. 앱은 구간만 고르고 서버가 자른다. [Claude 판단]

- `POST /analyses`에 선택값 `trim_start`, `trim_end`(초)를 추가한다. `analyses` 표에도 저장한다.
- 조건: `0 <= start < end`, `end - start <= max_video_seconds`. 어기면 400 `INVALID_TRIM`.
- `normalize`가 구간을 먼저 자른 뒤 길이를 검사한다. 구간이 영상 끝을 넘어서 남는 길이가 없으면 기존 영상 오류와 같은 방식으로 실패한다.
- 레포트의 시각은 잘린 재생 영상 기준이다.
- 한계: 원본 전체를 올리므로 200MB 제한은 그대로다.
- 값을 보내지 않는 웹은 지금과 똑같이 동작해야 한다.

## 앱 기능

### 로그인

`@clerk/expo`의 `useSignIn`, `useSignUp`, `useSSO`로 직접 만든다. 토큰은 `expo-secure-store`에 저장한다.
Google 로그인은 Expo Go에서 되지 않으므로 개발 빌드를 쓴다. Clerk Native applications 설정과 redirect URL 허용을 추가한다.

### 영상 분석

1. 갤러리나 공유 메뉴에서 영상을 고른다. 두 경로 모두 같은 업로드 화면으로 들어간다.
2. 동의를 받고 필요하면 구간을 고른다.
3. `POST /analyses` → 서명 URL로 PUT → `POST /analyses/{id}/submit`
4. 상태를 폴링해 단계와 결과를 보여 준다.

업로드 실패 때는 새 분석을 만들지 않고 같은 서명 URL로 다시 시도한다. 분석을 새로 만들면 하루 한도가 줄기 때문이다. 서명 URL 유효시간 15분이 지나면 다시 만든다.
`playback_url`이 만료되면 분석을 다시 불러온다. 오류는 API의 `code`로 분기한다.

### 레포트 공유

앱에서 레포트 JSON을 HTML로 바꾸고 `expo-print`로 PDF를 만든 뒤 공유 메뉴를 연다. 서버 변경은 없다.
웹 레포트의 참고용 안내 문구를 PDF에도 그대로 넣는다. 영상과 이미지는 넣지 않는다. [Claude 판단]

### 사고 현장 모드

로그인 없이 쓸 수 있고 인터넷이 없어도 동작한다. 기록은 폰에만 저장하고 서버로 보내지 않는다. [Claude 판단]

- 체크리스트: 비상등과 안전한 곳으로 대피, 부상 확인, 신고, 현장 촬영, 보험사 연락
- 112, 119, 사용자가 저장한 보험사 번호로 전화
- 사진 촬영: 시각과 위치를 함께 저장. 위치 권한을 거부해도 사진은 저장한다.
- 기록 목록, 공유, 삭제

### 상품 구매

`expo-web-browser`로 `https://aigo.up.railway.app/#products`를 연다. 웹에는 상품 목록 전용 페이지가 없고 첫 화면의 구역만 있다. 앱 로그인이 공유되지 않아 웹에서 다시 로그인할 수 있다.

## 나중에 할 일: DashPi 영상 받기

DashPi 기획이 끝나지 않아 이번 범위에서 뺀다. [사용자]
추후 DashPi가 영상을 서버로 올리면 앱이 그 영상을 받는 기능을 만든다. [사용자] 이번 구현에는 이 기능을 위한 코드를 넣지 않는다.

## 구현 순서

1. Expo Router 기본 구조, 로그인, 토큰으로 `/me` 호출
2. 영상 선택, 업로드, 분석 상태, 레포트, 내역, 삭제, 탈퇴
3. 레포트 공유, 상품 페이지 연결
4. 구간 자르기(API, worker, 앱)
5. 사고 현장 모드
6. 푸시(API, worker, 앱)
7. 공유 메뉴로 영상 받기

앞 단계에서 로그인이 막히면 뒤 단계도 검증할 수 없으므로 1번을 가장 먼저 끝낸다.

## 검증

- API: 기존 pytest에 인증, 기기 등록, 푸시 실패 격리, 구간 자르기 테스트를 추가한다.
- 앱: TypeScript 검사, 로직 단위 테스트, `expo-doctor`, Android 번들 빌드
- 전체 흐름: Android 에뮬레이터에서 실제 배포 API로 로그인부터 레포트까지 확인한다.
- 웹: 변경 뒤 `https://aigo.up.railway.app`에서 분석 흐름이 그대로 되는지 확인한다.
