# AIGO 모바일 앱 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 기존 AIGO API를 쓰는 Expo 앱에 로그인, 영상 분석, 레포트 공유, 구간 자르기, 사고 현장 모드, 푸시, 공유 메뉴 받기를 넣는다.

**Architecture:** `apps/app`은 웹과 같은 `/api/v1` 클라이언트다. API에는 앱 토큰 허용, 기기 등록, 완료 푸시, 구간 자르기만 추가한다. 사고 현장 기록은 폰에만 저장한다.

**Tech Stack:** Expo SDK 58, Expo Router, `@clerk/expo`, TypeScript, jest-expo, FastAPI, SQLAlchemy, Alembic, FFmpeg

**Spec:** `docs/superpowers/specs/2026-11-06-aigo-app-design.md`

## Global Constraints

- 사용자에게 보이는 문구와 코드 주석은 한국어로 쓴다.
- Clerk 기본 UI는 쓰지 않는다.
- UI는 기능 확인용 기본 화면만 만든다. 디자인 작업은 하지 않는다.
- DashPi 기기 연결 코드는 넣지 않는다.
- 비밀값은 Git 무시 파일에만 둔다. 저장소는 공개 상태다. 사고 영상, 키, 서명 URL을 커밋하거나 출력하지 않는다.
- 오류 분기는 API의 `code`로 한다.
- 패키지는 `npx expo install`로 SDK 58에 맞는 버전을 설치한다. 패키지 관리자는 pnpm이다.
- 작업 브랜치는 `dev`에서 만든다. `main`은 건드리지 않는다.
- API를 바꾸면 `apps/web/openapi.json`과 `apps/web/lib/api.gen.ts`를 다시 생성한다. 웹 동작은 바뀌면 안 된다.

## Review Focus

1. 인터넷이 없을 때 사고 현장 모드를 열면 Clerk 로딩을 기다리지 않고 바로 떠야 한다.
2. 레포트 문구에 `<`, `&`가 있어도 PDF HTML이 깨지거나 태그로 해석되면 안 된다.
3. 같은 폰에서 다른 계정으로 로그인하면 푸시 토큰이 새 사용자로 옮겨 가야 한다.
4. 업로드가 끊기면 새 분석을 만들지 않고 재시도해야 한다. 분석을 하나 더 만들면 하루 한도가 줄어든다.
5. 폴링 중 다른 기기에서 분석을 지워 404가 오면 무한 재시도 없이 목록으로 돌아가야 한다.
