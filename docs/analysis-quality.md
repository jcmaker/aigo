# 분석 품질 개선

상태와 다음 작업을 정리한다. 2026-11-08에 충돌 추정을 넣고 다시 측정했다(맨 아래 절).

## 현재 상태

품질은 아직 합격선에 미달한다. 정답은 아직 팀이 확인하지 않은 초안이고(`apps/api/eval/golden.json`의 `checked_by`가 모두 비어 있음), 표본도 작다.

| 지표 | 합격선 | 현재 (25개, 2026-11-08) |
|---|---|---|
| 충돌 시각 1초 이내 | 80% | 7/18 |
| 정답 도표 선택 | 70% | 1/6 |
| 정답 과실이 범위 안에 포함 | 70% | 0/5 |
| 사고 없는 영상에 과실 표시 | 0건 | 0/7 |
| 근거 시각 일치 | 표본 30개 이상, 90% | 38/39 (97%) |

원본 결과는 `apps/api/eval/results/`에 있다. 측정 조건은 gpt-5.5, 추론 low, 프롬프트 `2026-11-06.2`다. 아래 "원인"과 "다음 작업"은 2026-11-05 기준 기록이며, 이번 개선은 맨 아래 2026-11-08 절에 있다.

## 원인

**사고 영상의 대부분을 "사고 장면 없음"으로 판단한다.** 정답이 `party`인 영상 18개 중 12개를 `none`으로 냈다. 오탐은 없지만, 충돌을 놓쳐 그 뒤 단계(도표, 과실)가 시작조차 하지 않는다.

블랙박스에는 접촉 순간이 잘 찍히지 않는다. 차가 화면 가장자리나 사각에서 스치기 때문에, 프레임만 보는 지금 방식으로는 충돌을 확인하지 못한다.

2026-11-07 운영 시험에서도 같은 영상이 전체로는 "진로변경 중 충돌", 0~15.8초로 자르면 "사고 장면 미확인"으로 나왔다.

## 다음 작업: 충돌 추정

접촉 장면이 보이지 않아도 아래 근거가 함께 나타나면 "충돌 추정"으로 판단한다. 보이는 사실만 쓴다는 원칙은 유지하고, 추정은 추정이라고 레포트에 표시한다.

- 소리: 충돌음 크기와 시각
- 화면 흔들림: 카메라 자체의 급격한 움직임
- 충돌 뒤 움직임: 상대 차의 급정지, 궤적 꺾임, 내 차 감속

작업 순서는 다음과 같다.

1. 팀이 정답 라벨을 확인한다(`checked_by` 채우기). 특히 `unsure`와 `note`에 "팀 판단 필요"가 적힌 항목.
2. 위 근거를 `apps/api/app/pipeline/`(`scan.py`, `locate.py`)에 추가한다.
3. 전체 재측정을 한다. 약 $10 정도이며, 사용자 승인 뒤 실행한다.
4. 합격선을 넘으면 README의 평가 결과를 갱신한다.

측정 명령은 `cd apps/api && uv run python -m app.evaluate --videos <폴더>`다. 다시 채점만 할 때는 `--rescore eval/results/<시각>.json`이며 비용이 들지 않는다. 영상은 저장소에 넣지 않는다(`eval/videos/`는 git 무시).

## 웹과 앱에 미치는 영향

분석은 worker에서만 돈다. 그래서 레포트 형식을 바꾸지 않으면 worker 배포만으로 웹과 앱이 함께 좋아진다.

- **레포트에 항목을 추가할 때:** 웹, 앱 화면, 앱 PDF(`apps/app/src/lib/report-html.ts`)를 함께 고친다. 앱은 새 APK가 필요하다. 이미 설치된 앱이 깨지지 않게, 기존 항목은 바꾸지 말고 추가만 한다.
- **DB를 바꿀 때:** API를 먼저 배포해 마이그레이션을 적용하고, 그 뒤 worker를 배포한다.
- **이미 끝난 분석:** 다시 분석해야 결과가 바뀐다. 결과가 어느 버전으로 만들어졌는지는 `analyses.pipeline_version`으로 구분한다.

## 2026-11-08 충돌 추정 재측정

**초안 정답 기준.** 같은 25개 영상(채점 대상), 같은 모델·프롬프트로 다시 측정했다.

| 지표 | 합격선 | 이전 (11-05) | 이번 (11-08) |
|---|---|---|---|
| 충돌 시각 1초 이내 | 80% | 3/18 | 7/18 |
| 정답 도표 선택 | 70% | 1/6 | 1/6 |
| 정답 과실이 범위 안에 포함 | 70% | 0/5 | 0/5 |
| 사고 없는 영상에 과실 표시 | 0건 | 0/7 | 0/7 |
| 관여 판정 일치 | - | 10/25 | 14/25 |
| 근거 시각 일치 | 30개 이상, 90% | 미측정(참고 21/26) | 38/39 (97%) |

결과 파일은 `eval/results/20261108T105500Z-estimate.*`와 근거 시각을 채점한 `...-estimate-rescore-20261108T110844Z.*`다. 근거 시각 판정 26개는 `eval/evidence_checks.json`에 추가했고(`checked_by`는 "claude(초안)"), 사람 확인은 아직 아니다.

### 후보 단계 분석

충돌음, 흔들림, 상자 겹침, 급정지 신호로 만든 후보에는 사고 영상 18개 중 16개(조정 뒤 17개)가 정답 1초 이내 후보를 갖고 있었다. 이전 측정에서 충돌 시각을 놓친 15개 중 13개는 후보까지는 있었고 판단 단계에서 잃었다. 즉 병목은 신호 검출보다 "프레임에 접촉이 안 보인다"는 판단이었다.

### 바꾼 것

- 상대 차 급정지(감속) 신호 추가, 신호별 시각 보존
- 흔들림과 충돌음이 함께 강하면(0.4초 안) "충돌 추정"으로 표시. 급정지는 내 급제동(아차사고)에서도 흔들림과 함께 커져서 발동 조건이 아니고, 같은 범위에서 강하면 근거 사실("앞차와의 거리가 급히 좁혀진 뒤 멈춤")로만 붙는다. 가중치와 임계값은 tuned 분할에서 골랐다(WEIGHTS box .4/motion .3/audio .2/decel .1, STRONG .45). 무사고 영상 추정 0을 조건으로 했다.
- 근거 시각 검증 보강, 센서 근거 분리 집계
- 도표별 관련 법규와 참고 판례를 레포트에 표시

### 추정이 켜진 영상

이전에 관여를 `none`으로 냈다가 이번에 `party`(충돌 시각)로 바뀐 영상은 5개이고 모두 정답 1초 이내다. 그중 4개가 충돌 추정으로 바뀌었다.

| 영상 | 추정 시각 | 정답 |
|---|---|---|
| ARwU | 12.6 | 12.4 |
| DwEN | 12.4 | 11.8 |
| EQwC | 10.4 | 10.4 |
| HgsR | 9.6 | 9.7 |

ChYn(8.0초, 정답 7.9초)은 추정이 아니라 관찰로 확인했다.

정답이 미정인 영상:

- AAAL: 10.4초(충돌음 + 흔들림, 급정지는 근거로 덧붙음). 미정. 사람이 정답을 확인해야 맞는지 알 수 있다.
- Cgsf: 이전 규칙(흔들림 + 급정지)에서 14.8초로 추정이 켜져 도표 차43-2, 과실 0~50을 표시했지만 프레임에는 접촉이 없었다. 이번 수정(흔들림 + 충돌음만 발동)으로 추정에서 제외했다(후보 JSON으로 오프라인 확인, 재측정은 하지 않음).

무사고 정답 영상에서는 켜진 곳이 없다(0/7). 수정 뒤 오프라인 확인에서도 사고 영상 추정(ARwU, DwEN, EQwC, HgsR 포함)과 무사고 0은 그대로다.

### 남은 문제

- 정답 도표 1/6, 정답 과실 범위 0/5. 충돌 시각이 맞아도 도표 단계에서 "미정"으로 끝나는 영상이 대부분이다.
- 충돌 시각 7/18은 합격선(80%)에 한참 못 미친다. 나머지는 센서 신호가 약하거나 후보 순위가 낮다(원인은 추가 확인 필요).
- 접촉이 아예 안 보이는 사고 영상(AA8U 등)은 여전히 `none`으로 나온다.
- MIN_SCORE를 0.25로 낮추면 상자만 있는 후보(`test_car_leaving_frame_finds_collision`)를 살리지만 후보 재현율이 17/18에서 16/18로 준다. 그래서 두지 않았다.
