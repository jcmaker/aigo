# 0009. 인증은 Clerk, 화면은 직접 만든다

- 상태: 채택
- 날짜: 2026-11-05
- 변경 작업자: 조준형 (jcmaker) 결정, Claude(AI) 세부 설계 후 조준형 승인
- 관련: 설계 2026-11-05 4장, PR #3, #10, #23

## 작업 내용
- 인증은 Clerk 개발 모드입니다. 이메일 로그인과, 공급자 콘솔 설정 없이 켤 수 있는 소셜 로그인(Google, Apple, Facebook)을 씁니다.
- Clerk 기본 UI는 쓰지 않습니다. 로그인, 가입, 이메일 코드, 소셜 버튼, 프로필 화면을 웹과 앱 디자인으로 직접 만들고 Clerk 훅과 API로 연결합니다.
- 웹과 앱은 세션 JWT를 `Authorization: Bearer`로 api에 보냅니다. api는 Clerk 공개키로 검증하고, 처음 보는 사용자는 `users` 행을 자동으로 만듭니다.
- 쿠키를 쓰지 않고, 웹은 CORS로 api를 직접 부릅니다. 허용 출처는 web 주소만 둡니다.
- 탈퇴(`DELETE /me`)는 파일 → DB → Clerk 사용자 순서로 지웁니다.

## 변경 사유
- Clerk와 맞춤 화면은 조준형이 정했습니다. 서비스 디자인과 맞지 않는 기본 UI를 피하려는 것입니다.
- Bearer 토큰 방식은 웹과 앱이 같은 방법으로 인증하게 해 줍니다.
- Kakao 로그인은 Clerk 공유 자격 증명을 확인하지 못해 뺐습니다.

## 영향
- 공급자별 개발자 콘솔 설정이 필요한 소셜 로그인은 하지 않습니다.
- DashPi 기기는 세션 대신 API Key로 인증합니다(ADR 0021).
