# 0011. 사고 분석 원칙과 파이프라인

- 상태: 채택
- 날짜: 2026-11-05
- 변경 작업자: 조준형 (jcmaker) 결정, Claude(AI) 세부 설계 후 조준형 승인
- 관련: 설계 2026-11-05 5장, PR #5, #6, #7, #11

## 작업 내용
분석 원칙:
1. 입력을 먼저 고칩니다. 30fps 고정 mp4로 정규화하고 재생용 720p를 따로 만듭니다.
2. 충돌 순간을 먼저 찾습니다. 넓게 훑고(초당 5장, YOLO와 ByteTrack) 후보 구간만 촘촘히 봅니다(초당 15장).
3. 관찰과 판단을 나눕니다. 모델은 프레임에서 보이는 사실만 시각과 함께 적고(`observe`), 그 사실로만 판단합니다(`assess`).
4. 숫자는 코드가 계산합니다. 모델은 도표와 수정요소를 고르기만 하고, 과실 범위는 코드가 냅니다.
5. 모르면 모른다고 합니다. 근거가 없으면 `unknown`, 맞는 도표가 없으면 과실비율을 내지 않습니다.
6. 모든 주장에 근거 시각을 붙입니다. 시각이 없거나 영상 범위를 벗어난 주장은 코드가 버립니다.
7. 신뢰도는 모델에게 묻지 않고 코드가 정합니다.
8. 측정 없이 바꾸지 않습니다. 프롬프트, 모델, 샘플링을 바꾸면 평가 세트(`python -m app.evaluate`)를 다시 돌립니다.

단계: `normalize` → `scan` → `locate`(충돌 후보 최대 3개) → `focus` → `observe` → `assess`. 모델은 OpenAI이고 `OPENAI_MODEL` 환경변수로 바꿉니다.
레포트에는 "영상 기반 AI 추정이며 법적 판단이 아닙니다"를 항상 표시합니다. 이 문구는 모델 출력이 아니라 화면 코드에 둡니다.

## 변경 사유
- 기존 `video_ai`와 `accident-counsel`은 참고만 하라고 조준형이 정했습니다. `video_ai`는 빠르게 만든 프로토타입이라 입력 품질이 낮으면 결과도 나빠집니다.
- 전체를 균등하게 몇 장 뽑으면 짧은 접촉 순간을 놓칩니다.
- AI 추정을 법적 판단처럼 보이거나, 사고가 아닌 영상에 그럴듯한 레포트를 지어내는 것을 실패로 봅니다.

## 영향
- 사고 없는 영상에 과실을 내는 것은 0건이어야 합니다. 이 조건이 다른 지표보다 앞섭니다.
- 합격선(충돌 시각 80%, 도표 70% 등)은 초기값이고, 2026-11-08 기준 일부 지표는 아직 미달입니다(`docs/analysis-quality.md`).
