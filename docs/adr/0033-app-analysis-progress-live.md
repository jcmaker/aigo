# 0033. 분석 진행 화면을 단계 안에서도 움직이는 체크리스트로 바꾼다

- 상태: 채택
- 날짜: 2026-11-21
- 변경 작업자: 조준형 (jcmaker), Claude(AI)
- 관련 PR: (PR 번호)

## 작업 내용
앱 분석 진행 화면(`components/analysis.tsx`의 `ProgressView`, `components/ui/StepList.tsx`)을 바꿨다.

- 위 카드: 반원 게이지 대신 `n/6 단계` · `경과 m:ss` 한 줄, 큰 제목("AI가 장면을 읽고 있어요"), 2.6초마다 바뀌는 안내 문구, 차오르는 진행 막대(빛 띠가 지나감).
- 단계 목록: 진행 중 단계는 번호 둘레를 링이 돌고 오른쪽에 그 단계의 경과 초, 아래에 안내 문구를 보인다. 끝난 단계는 체크가 튀어나오듯 나타나고 결과 문구를 보인다.
- 계산은 `lib/progress.ts`의 순수 함수(`liveProgress`, `hintAt`)로 뗐다. 1초 타이머(`lib/use-now.ts`)는 화면이 보일 때만 돌고, "동작 줄이기"(`lib/use-reduce-motion.ts`)가 켜져 있으면 회전·빛·튀어나옴을 끈다.
- 단계 문구를 "~하고 있어요"체로 바꾸고, 단계마다 안내 문구 2~4개를 더했다(`lib/analysis.ts`의 `STAGES`).
- 쓰지 않게 된 `stageSegments`를 지웠다.

## 변경 사유
분석 중 화면은 단계가 바뀔 때만 달라져, AI를 부르는 단계(수십 초) 동안 사용자는 멈췄는지 진행 중인지 알 수 없었다(조준형 요청). 시안 세 가지(살아 있는 체크리스트, 레포트 스켈레톤, AI 작업 기록)를 비교해 서버를 바꾸지 않고 바로 적용할 수 있는 체크리스트를 골랐다. 시안: https://claude.ai/artifact/BCC9RkcmLpTRDjEvwXtcR9

## 영향
- 서버와 API는 그대로다. 경과 시간은 서버가 기록한 단계 시각(`progress[].at`)으로 센다. 대기열에서는 세지 않는다.
- 안내 문구는 실제 측정값이 아니므로 숫자를 넣지 않는다. 진행 막대는 완료 전까지 100%가 되지 않는다.
- 끝난 단계의 소요 초는 보이지 않는다. 서버가 완료 때 시각을 덮어써 첫 단계의 시작을 알 수 없다.
- 단계별 예상 시간(`EXPECTED_SEC`)은 추정값이다. 운영 로그로 재면 바꾼다.
- 웹 분석 화면은 바뀌지 않았다(따로 한다).
