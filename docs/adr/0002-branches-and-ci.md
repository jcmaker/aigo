# 0002. dev/main 브랜치, CI, 브랜치 보호

- 상태: 채택
- 날짜: 2026-11-09
- 변경 작업자: 조준형 (jcmaker)
- 관련 PR: #54, #55, 가드레일 PR

## 작업 내용
- 브랜치는 `dev`(기본)와 `main` 둘입니다. 기능별 PR을 `dev`에 머지하고, 확인이 끝나면 `dev`를 `main`에 머지합니다.
- GitHub Actions가 PR마다 검사합니다: API 테스트, 웹 테스트·빌드, 앱 검사(`ci.yml`), PR 가드레일(`pr-guardrail.yml`).
- `dev`와 `main`은 보호됩니다: PR로만 머지, CI 통과 필수, CODEOWNERS(jcmaker) 승인 필수, 강제 푸시와 삭제 금지.
- CI는 비밀값을 쓰지 않고 읽기 권한만 씁니다.

## 변경 사유
팀원이 협업자(write)로 참여합니다. 관리자 승인 없이 머지되거나, 테스트가 깨진 코드가 들어가는 것을 막아야 합니다. 저장소가 공개라 외부 PR도 들어옵니다.

## 영향
- 팀원은 직접 머지할 수 없습니다. 관리자가 확인하고 머지합니다.
- 관리자는 보호 예외라서 자기 PR을 `gh pr merge --admin`으로 머지합니다.
