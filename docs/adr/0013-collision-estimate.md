# 0013. 센서 신호로 충돌 추정, Jev는 쓰지 않는다

- 상태: 채택
- 날짜: 2026-11-08
- 변경 작업자: 조준형 (jcmaker) 결정, Claude(AI) 세부 설계 후 조준형 승인
- 관련: 설계 `docs/superpowers/specs/2026-11-08-analysis-quality-design.md`, `docs/analysis-quality.md`, PR #41, #42, #44, #45, #46

## 작업 내용
- 충돌 후보 신호에 상대 차 급정지(decel)를 더했습니다. 신호는 상자 급변(0.4), 화면 흔들림(0.3), 충돌음(0.2), 급정지(0.1)입니다.
- 프레임에서 접촉이 안 보여도 흔들림과 충돌음이 0.4초 안에 함께 강하게 잡히면 "충돌 추정"으로 판단을 이어 갑니다.
  - 관찰이 `none`이거나 접촉을 확인하지 못한 `party`일 때만 씁니다. `witness`나 추적 객체가 없을 때는 쓰지 않습니다.
  - 추정이면 신뢰도를 "낮음"으로 고정하고 요약 앞에 "충돌 추정:"을 붙입니다.
  - 추정 시각 곁에 프레임 사실이 없으면 과실비율을 내지 않습니다.
  - 센서 사실은 판단 모델에 넣지 않고 코드가 타임라인에 붙입니다.
- Jev 같은 외부 판단 모델은 도입하지 않았습니다.

## 변경 사유
- 정답이 사고인 영상 18개 중 12개가 "사고 장면 미확인"으로 끝났습니다. 블랙박스에는 접촉 순간이 잘 찍히지 않습니다.
- 조준형이 사람이 충돌을 알아채는 단서로 충돌음, 화면 흔들림, 상대 차 급정지를 꼽았습니다.
- 흔들림과 충돌음을 함께 요구한 것은 오탐을 막기 위해서입니다. 급정지는 내 급제동(아차사고)에서도 흔들림과 함께 커집니다. 이전 규칙(흔들림 + 급정지)은 접촉이 보이지 않는 영상(Cgsf)에 과실 0~50%를 냈습니다. 그래서 급정지는 발동 조건에서 빼고 근거 사실로만 붙입니다.
- Jev: 입력이 숫자 몇 개이고 평가 사고 영상이 18개뿐이라 규칙과의 차이를 확인하기 어렵고, 작업량에 비해 품질 이득이 불확실합니다. 조준형이 "큰 차이를 못 느끼면 안 쓰는 게 낫다"는 쪽을 골랐습니다.

## 영향
- 초안 정답 기준으로 충돌 시각 1초 이내 3/18 → 7/18, 사고 없는 영상 과실 0/7을 유지했습니다.
- 정답 확인 영상이 100개 이상 쌓이고 규칙이 더 오르지 않으면 Jev를 다시 검토합니다.
- 품질 측정의 OpenAI 비용은 25달러 안에서 합니다(ADR 0019).
