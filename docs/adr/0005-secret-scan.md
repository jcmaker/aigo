# 0005. 비밀값 검사와 자동 댓글

- 상태: 채택
- 날짜: 2026-11-09
- 변경 작업자: 조준형 (jcmaker)
- 관련 PR: 비밀값 검사 PR

## 작업 내용
- "비밀값 검사" 워크플로(`.github/workflows/secret-scan.yml`)가 `dev`·`main`으로 가는 PR과 푸시를 검사합니다.
- gitleaks 8.30.1(SHA-256 고정)의 기본 규칙에 이 저장소 규칙을 더했습니다(`.gitleaks.toml`): Clerk 비밀키, 토스 비밀키, 비밀번호가 들어간 DB 주소.
- 공개해도 되는 값은 예외입니다: Clerk 공개키(`pk_…`), 토스 테스트 클라이언트 키(`test_gck_…`), `localhost` DB 주소.
- `.env`, `.env.local`, `*.keystore`, `*.pem`, `*.key` 같은 파일을 추가하거나 고쳐도 실패합니다(`.env.example`은 괜찮음).
- PR에서 실패하면 봇이 PR에 댓글을 답니다. 파일, 줄, 종류, 커밋을 적고, 지우는 법과 키 폐기를 안내합니다. 비밀값 원문은 적지 않습니다. 다시 검사해 통과하면 같은 댓글을 "통과"로 바꿉니다.
- PR 커밋 전체를 검사합니다. 지우는 커밋을 더해도 앞 커밋에 값이 남으면 실패합니다.
- 검사는 기준 브랜치의 설정과 스크립트로 합니다. PR에서 `.gitleaks.toml`을 고쳐도 검사를 피할 수 없습니다. PR 코드는 실행하지 않습니다.
- `dev`·`main` 브랜치 보호의 필수 검사에 넣었습니다.

## 변경 사유
비개발자 팀원이 실수로 키나 비밀번호를 커밋하거나 PR에 올릴 수 있습니다. 저장소가 공개라 올라간 값은 바로 노출됩니다. 조준형이 한 번 검수하고, 통과하지 못하면 없애 달라는 댓글이 자동으로 달리게 해 달라고 요청했습니다.

## 영향
- 2026-11-09 기준 저장소 전체 기록을 이 설정으로 검사해 걸린 것이 없습니다.
- 잘못 걸리는 값이 생기면 관리자가 `.gitleaks.toml` 예외에 더합니다.
- 이미 올라간 키는 이 검사로 되돌릴 수 없습니다. 발급한 곳에서 폐기하고 새로 받아야 합니다.
