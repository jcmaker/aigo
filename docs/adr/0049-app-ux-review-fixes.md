## 작업 내용
1. 리포트 머리글(`app/analyses/[id].tsx`): 완료된 분석은 사고 이름 대신 "분석 리포트"를 제목으로 둔다(아래 줄 "내 차 사고 · 날짜"는 그대로). 사고 이름은 남색 요약 카드에만 보인다. 실패한 분석은 실패 제목을 그대로 둔다.
2. 영상 분석하기(`app/(tabs)/upload.tsx`): "올리고 분석 시작"이 눌리지 않을 때 바로 위에 이유를 한 줄로 보인다("1번에서 영상을 고르면 누를 수 있어요" / "2번에서 동의하면 누를 수 있어요").
3. 동의(`ui/Notice`, `ui/ConsentSwitch`): 안내 글씨 12.5 → 15px, 스위치 44×26 → 52×30, 동의 문구 15px, 줄 높이 48 이상(줄 전체를 눌러 켜고 끈다).
4. 작은 글씨: 상태 칩(`ui/Chips`의 `StatusChip`) 11.5 → 13px, 진행 단계(`ui/StepList`) 이름 15px·설명 13 → 14px·번호 13px.
5. 하단 메뉴(`ui/FloatingTabBar`): 아이콘 밑에 글자(홈, 내 분석, 사고 현장, 분석하기, 계정, 12px)를 넣는다. 칸 46×46 → 62×54. "사고 현장 모드"는 칸이 좁아 화면 글자만 "사고 현장"으로 줄이고, 읽기 문구는 "사고 현장 모드" 그대로다. 메뉴 높이가 늘어난 만큼 `tabBarSpace`를 78 → 86으로 늘렸다.
6. 근거 탭 타임라인(`report-sections`의 `VerticalTimeline`): 장면마다 붙던 "눌러서 이 장면으로 이동"을 뺐다. 카드 설명("항목을 누르면 그 장면으로 이동해요")에 한 번 있다. 읽기 문구는 그대로다.
7. 사고 현장 모드(`SceneBody`): 아래 고정 112·119 버튼 높이 56 → 48, 맨 아래 여백 64 → 72. 사진 저장 알림 위치도 맞췄다.
8. 홈(`app/(tabs)/home.tsx`): "DashPi 기기 · 준비 중" 줄을 뺐다. 기기 연결 기능이 들어오면 다시 넣는다.

## 변경 사유
#98·#99 수정 뒤 앱 전체를 다시 검토했다(최혜지 요청). 긴 사고 이름이 머리글에서 단어 중간에 줄바꿈되고 같은 이름이 바로 아래 카드에 또 나왔다. 회색 버튼은 왜 안 눌리는지 알 수 없었다. "글씨 크게" 방향과 달리 11~13px 글씨가 남아 있었다. 하단 메뉴가 아이콘만 있어 처음 쓰는 사람이 무슨 버튼인지 알기 어려웠다. 근거 장면마다 같은 안내가 반복됐다. 112·119 띠와 하단 메뉴가 화면 아래를 많이 덮었다. DashPi 줄은 누를 일이 없는데 홈 한 줄을 차지했다.
